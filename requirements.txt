# Exact pins, not ranges (Gate 7, Item 61 of the Duroflex pilot readiness
# list - see PI3_Application_Changes_Needed.docx, section 3.2): a bare
# range silently resolves to whatever's newest on PyPI on the day someone
# runs `pip install`, which is exactly how the streamlit/pandas/pyarrow
# incident below happened in the first place. Every version below was
# confirmed on 2026-08-03 to resolve together with no conflicts (`pip
# install --dry-run` against this exact file). Bumping any pin here is a
# deliberate action, not something that happens automatically on the next
# deploy - re-run that same dry-run check (or a real install) before
# raising any of these, especially streamlit/pandas/pyarrow together (see
# the history below) and reportlab (major version 5.0.0, bumped from the
# 4.x this app was originally built against - re-verify PDF report
# generation, reports.py, after ANY reportlab version change).
#
# History kept for context - see also the "dependency drift"
# troubleshooting entry in README.md. Streamlit Community Cloud forces the
# Python version (no runtime.txt support) and had moved to Python 3.14 by
# 2026-07-31; Streamlit only gained real Python 3.14 support in 1.60.0 (a
# PEP 649 deferred-annotation-evaluation fix), so streamlit MUST be >=1.60
# here or the app silently fails to route through its own
# st.navigation()/sidebar code on Cloud (no traceback - it just falls back
# to Streamlit's default flat page list and default centered layout, which
# is what made this so confusing to diagnose). Separately, pandas 3.0
# changed Arrow/dtype handling strictly enough to crash a real page
# (Subscription Types, mixed int/str column - also fixed in code), so
# pandas stays below 3.0. Verified 2026-07-31 that
# streamlit>=1.60,<1.61 + pandas<3.0 + pyarrow<25 resolves cleanly together
# (streamlit 1.60.0 / pandas 2.3.3 / pyarrow 24.0.0) - pinned exactly to
# that combination below.
#
# 2026-08-04: numpy==2.2.6 and scipy==1.15.3 (the versions in use since the
# Trend Analysis feature) predate PyPI's Python 3.14 wheel builds for those
# two packages, so Streamlit Cloud's `uv pip install` fell back to building
# scipy from source - which needs a Fortran compiler (gfortran) that isn't
# present in the Cloud build image, so the deploy failed outright ("Unknown
# compiler(s): [gfortran, ...]"). numpy alone can build from source without
# Fortran (slow but works), which is why only scipy's build actually
# errored. Bumped both to the first release line carrying real cp314
# wheels (confirmed on pypi.org: numpy 2.5.1 and scipy 1.18.0 both ship
# manylinux_2_27/2_28 x86_64 cp314 wheels) so Cloud installs a prebuilt
# wheel instead of compiling anything. scipy's only call site is
# analytics.py's `scipy_stats.linregress` (Trend Analysis trend test) -
# that API is unchanged across this range.
streamlit==1.60.0
# starlette is one of streamlit's own dependencies (declared as
# starlette<2,>=0.40.0 - a wide, unpinned-by-us range) - normally not
# something this file needs to pin directly. Forced to pin it explicitly
# 2026-08-05: starlette 1.4.0 added a new required keyword-only argument
# (thread_minimum_size) to its internal GZipResponder.__init__, which
# streamlit 1.60.0's own vendored _MediaAwareGZipResponder subclass (in
# streamlit/web/server/starlette/starlette_gzip_middleware.py) does not
# pass - so with no pin here, `uv pip install` resolves to the newest
# starlette satisfying streamlit's own range (1.4.0), and the app throws
# "TypeError: GZipResponder.__init__() missing 1 required keyword-only
# argument: 'thread_minimum_size'" on every single request, immediately
# after boot, with no traceback in the app's own code (this is entirely
# an incompatibility between streamlit 1.60.0 and a too-new starlette,
# not a bug in this app). Fix: pin to the last starlette release before
# that breaking change (1.3.1) - confirmed by testing streamlit 1.60.0
# against starlette 1.3.1 directly: the server boots and responds 200 to
# its own health check with no GZip error. Re-verify this pin any time
# streamlit itself is upgraded past 1.60.0.
starlette==1.3.1
